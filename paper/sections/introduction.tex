\section{Introduction}
\label{sec:introduction}

Agent-based models (ABMs) represent a system as a population of autonomous agents that follow
local rules and interact through a shared environment \citep{macal2010tutorial}. Their appeal
is that aggregate patterns, such as an epidemic curve, a segregated city
\citep{schelling1971dynamic} or an unequal wealth distribution, emerge from rules a domain
expert can state and criticise. Their weakness is the cost of answering questions with them.
A single run tells little: a credible study runs many replicates per parameter combination,
explores the parameter space, fits the parameters to data, asks which of them matter, and
reports all of it in a form others can rerun. Each of these steps multiplies the number of
runs, and each is usually assembled by hand around the simulation library.

Python has become a common language for this work, and Mesa \citep{kazil2020mesa,
terhoeven2025mesa3} its best-known ABM framework. Python makes models easy to write and to
connect to the scientific stack \citep{harris2020numpy, virtanen2020scipy}, but per-agent
Python code is slow, and the surrounding tasks (sweeps, calibration, sensitivity analysis,
provenance) are left to the modeller or to separate tools \citep{herman2017salib,
klinger2018pyabc, kwakkel2017ema}. Faster platforms exist in Java and Julia
\citep{luke2005mason, north2013repast, datseris2024agents} and on GPUs
\citep{richmond2023flamegpu}; in Python, mesa-frames trades the per-agent programming model for
vectorised speed \citep{mesaframes}, and Repast4Py distributes a run over MPI processes
\citep{collier2020repast4py}.

\modelly{} implements a programming model compatible with Mesa's, so that a Mesa user is at
home and the mechanical part of porting a Mesa model is done by a codemod, and adds what is needed for speed and for
reproducible research:

\begin{itemize}[leftmargin=*,itemsep=2pt]
  \item \textbf{Performance without leaving Python.} Agent attributes can live in
  model-owned \code{numpy} arrays (\emph{columns}), identical agents can be counted rather
  than instantiated (\emph{cohorts}), and the framework's own inner loops run in small C
  modules, each with a pure-Python twin that gives the same results
  (\cref{sec:design}). \Cref{sec:performance} measures the gain on eight workloads against
  Mesa~2.3, Mesa~3.5, mesa-frames and hand-written numpy, says where it comes from, and checks
  that the faster forms compute the same model.
  \item \textbf{Reproducibility as a property of the framework.} Seeded generators reproduce
  the standard library's random stream, and a determinism suite checks that the bundled
  examples give the same digests compiled or in pure Python and straight or resumed from a
  checkpoint (\cref{sec:reproducibility}).
  \item \textbf{The study, not only the simulation.} Experiments, calibration, sensitivity
  analysis, provenance manifests, verifiable bundles and ODD skeletons \citep{grimm2006odd,
  grimm2020odd} are part of the package and share one seeding discipline, so their results do
  not depend on the executor or the number of workers, and a determinism suite compares the
  bundled examples' digests across builds and platforms (\cref{sec:workflow,sec:reproducibility},
  \cref{tab:determinism}).
  \item \textbf{A no-regression policy.} From version 1.3.1 on, each release is benchmarked
  against the previous one and must show no measurable regression on any core operation or
  workload (a median slowdown above 3\% whose lower quartile is also a slowdown); a pre-commit hook checks the core operations between
  releases (\cref{sec:regressions}).
  \item \textbf{What release 1.4 adds, with its shortfalls.} Per-agent random streams and
  split runs, a GPU backend, differentiable models, data assimilation, fields coupled to
  agents, emulators, synthetic populations and a browser export, each measured and each
  reported with what it does not yet do (\cref{sec:release14}).
\end{itemize}

The rest of the paper situates \modelly{} among existing tools (\cref{sec:related}),
describes its design (\cref{sec:design}) and research workflow (\cref{sec:workflow}),
evaluates its speed and its agreement with Mesa (\cref{sec:performance}) and the correctness
of its methods (\cref{sec:reproducibility}), reports what release 1.4 adds and where it
falls short (\cref{sec:release14}), states for which studies it is a good choice
(\cref{sec:usecases}), and ends with the threats to the validity of these measurements and the
software's limitations (\cref{sec:threats}).
