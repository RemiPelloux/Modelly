\section{Conclusion}
\label{sec:conclusion}

\modelly{} keeps the agent-based programming model that Python modellers know and changes what
it costs to use it in research: array-backed and counted populations for speed, compiled loops
with pure-Python twins, and the experiment, calibration, sensitivity, provenance and
publication steps built on one seeding discipline. Its claims are measured in the open: against
Mesa~2.3, Mesa~3.5 and mesa-frames, with an agreement study over 100 seeds per variant; against its own previous release
before every new one; and with methods checked on problems whose answers are known. Release
1.4 extends it beyond one process (split runs, a GPU backend, differentiable models) and
connects it to data, fields and the browser, each addition reported against the target its
roadmap set (\cref{tab:targets}). The
measurements also show where it does not help (a model written agent by agent runs between Mesa's speed and 4.6 times faster, depending on
how much of its time the framework's calls take; hand-written numpy that gives up agent
objects is 1.8 to 4.4 times faster than its columns; a split run on one laptop and a GPU below
tens of thousands of agents gain little) and where its evidence is still thin (\cref{sec:threats}).

\section{Availability}
\label{sec:availability}

\cmd{pip install modelly-abm} installs \modelly{} (Python 3.12 or later), which is imported as
\code{modelly} and is free software under the Apache 2.0 licence. Compiled wheels are published
for Linux, macOS and Windows, and a pure-Python wheel elsewhere. Source, issue tracker, the 2,929 tests (97.5\% line coverage, measured by the test suite's coverage job)
and the benchmark harness are at
\href{https://github.com/RemiPelloux/Modelly}{\nolinkurl{github.com/RemiPelloux/Modelly}};
documentation, tutorials and the roadmap at
\href{https://remipelloux.github.io/Modelly/}{\nolinkurl{remipelloux.github.io/Modelly}}. Fifty-five
tests skip without an optional library (CuPy, Ray, optuna, xarray, a broker) or a browser.
The version described here is 1.4.0. The
measurements of \cref{sec:performance} ran on the library code of 1.3.2 and 1.3.3 (which
1.4.0 keeps, apart from the changes gated in \cref{sec:regressions}), compiled on the
measurement machine with GCC~16.2, with the benchmark code of commit \code{627459a}; Mesa's examples were ported and timed with the
codemod fix of 1.3.3 and the runner of
\code{benchmarks/mesa\_examples/} before they were committed, unchanged (\code{19915bb},
\code{1e36264}), and the mesa-frames thread timing ran while the fix was uncommitted; the coverage study and
the numpy grid epidemic at the timed size ran while benchmark files they do not use were
uncommitted (since committed in \code{d45bbd3} and \code{0398c44}); each
result file records the commit, the machine and the package versions. The measurements of
\cref{sec:scale,sec:connect} ran in the branch of each addition before it was merged into
1.4.0, with the code committed unchanged; their result files record the environment and the
package versions, and the tests that reproduce them run in the merged tree. The data and scripts behind every table and figure
of this paper are in the repository's \code{paper/} folder (\cref{app:reproduce}). The repository
is archived by Software Heritage; the commit with the code, data and scripts of the
measurements of \cref{sec:performance,sec:reproducibility} is
\code{swh:1:rev:550458fe378d7f50147b}\allowbreak\code{1d6c4b5b1d49f3beddec}, and the 1.4
additions are in the commits that follow it.
