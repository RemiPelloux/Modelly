2.0.0: clean foundations#

Status: proposed · Base: 1.5.0

2.0.0 is the only release on this roadmap allowed to break things, and it breaks them on purpose and with a map. Three 1.x releases of features leave behind parallel ways of doing the same thing; 2.0 keeps the best one of each and makes it the only one. One space API, one clock, columns by default, typed scenarios, per-agent random streams, a stable C ABI and a checkpoint format that lasts. Every removal was deprecated in 1.5 at the latest, and modelly migrate --to 2.0 rewrites what can be rewritten. All on Windows, macOS and Linux (see Platforms).

Principles#

  1. No surprise breaks. Nothing is removed in 2.0 that did not warn in 1.5, naming the replacement.

  2. One way. Where 1.x grew two ways to do a thing, 2.0 keeps one.

  3. Same science. A model migrated to 2.0 gives statistically the same results as on 1.5; where the random streams change (per-agent streams), the migration guide says so and the agreement test (Welch, as in the playbooks) proves it.

  4. Faster everywhere. No playbook slower than 1.5 on any OS.

  5. Supported 1.x. 1.5 is a long-term-support line: it keeps receiving bug and security fixes after 2.0.0, so every user can migrate when their own work allows.

Epics#

H1 · Removals and the migration tool#

Goal: remove every deprecated name and make upgrading a command, not a project.

Work items: remove everything deprecated in 1.3 to 1.5; modelly migrate --to 2.0 (the codemod from modelly.migrate, extended to 1.x → 2.0 rewrites) with a dry run, a diff and a report of what needs a human; a migration guide with before/after for every removal; migration tested on every zoo and hub model.

Done when: every zoo model and the three community models migrate automatically, pass their validation tests, and agree with their 1.5 results.

Size: L

H2 · One space API#

Goal: grids, networks, continuous space and geographic space share one protocol: the same calls to place, move, query neighbours and iterate, whatever the geometry.

Design: a Space protocol (place, move, neighbors, within, positions as a column); discrete spaces keep cells, continuous and geographic spaces keep coordinates, both answer the same queries; property layers become fields (from 1.4 F6) on every space; old space classes kept as thin aliases through 2.x where they map cleanly.

Done when: every zoo model runs on the new protocol; a model can switch grid to network to continuous space by changing one line, verified by a tutorial.

Size: XL

H3 · Columns by default#

Goal: agent state lives in columns unless the model asks otherwise, so every model gets the 1.x column speed-ups without rewriting.

Design: typed attribute declarations (wealth: float = Column(0.0) or plain annotations) become columns automatically; attributes that cannot be columns (objects, lists) stay per-agent and are reported by modelly profile; DataCollector gathers columns without Python loops.

Done when: the classic playbook variants (per-agent code) run at least as fast as their 1.5 column variants after migration; no model loses an attribute in migration.

Size: L

H4 · One clock#

Goal: ticks and events on one scheduler with one documented ordering rule.

Design: steps are events at integer times; phases are priorities; tie-breaking is fully specified (time, priority, insertion order); the compiled scheduler from 1.4 is the only one; a schedule report shows what runs when.

Done when: every model with mixed ticks and events gives the same results as on 1.5 under the documented ordering; the ordering spec is a docs page with tests for each rule.

Size: M

H5 · Typed scenarios and configuration#

Goal: scenarios are typed, validated and loadable from files.

Design: Scenario as a dataclass_transform base (the default-type TODO in modelly/core/model.py that waits for Python 3.13); validation with clear errors (range, type, units); TOML and YAML loading; scenarios hashed into the manifest; sweeps over typed spaces.

Size: M

H6 · Per-agent random streams by default#

Goal: results independent of iteration order, partitioning and executor.

Design: opt-in in 1.4 (F1), default in 2.0; counter-based generators (Philox) keyed by run seed and agent id, shared by CPU and GPU; the model-level generators remain for model-level draws.

Done when: partition-independence holds for every space by default; agreement tests show the same distributions as 1.5 on every playbook.

Size: M · Depends on: 1.4 F1, F2

H7 · Stable ABI and native code#

Goal: one wheel per platform for every supported Python, and native code ready for every CPython build.

Design: the compiled modules move to the limited C API (abi3) where measurement shows no loss, keeping the version-specific build only where it matters; free-threaded builds are first-class; the private and unstable APIs left are inventoried and justified.

Done when: abi3 wheels for every row of the support matrix; no playbook slower than the version-specific build by more than 3%; a new CPython release installs on day one.

Size: M

H8 · Checkpoint and data formats v2#

Goal: a checkpoint written by 2.0 loads in every later 2.x release.

Design: a versioned, documented state format (columns as Arrow, structure as JSON, only user objects pickled); forward migrations between format versions; modelly checkpoint upgrade for 1.x files where the state maps; result stores and manifests versioned the same way.

Done when: a 2.0 checkpoint loads in a 2.1 test build; 1.5 checkpoints of every zoo model upgrade and resume with the same results.

Size: M

H9 · Python and platform baseline#

Work items: Python 3.13 minimum (3.12 dropped, as its own end of life approaches); a single test and release matrix covering every platform in the support table; installation verified on clean Windows, macOS and Linux machines with no compiler and no admin rights.

Size: S

H10 · Public API contract#

Work items: every public name listed in one place with its stability level (stable, provisional); the semantic-versioning promise written down; type-checked public API (strict); the plugin API v1 from 1.5 carried over unchanged.

Size: S

H11 · Documentation 2.0#

Work items: docs restructured around tasks (build, calibrate, scale, share, publish); every page tested (doctests and executed notebooks) on all three OSs; the migration guide and the “what is new in 2.0” tour; versioned docs keep /1.5/ as the LTS reference.

Size: M
