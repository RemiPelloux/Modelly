1.6.0: finish and bridge#

Status: in progress (S1) · Base: 1.5.1

1.6.0 sits between 1.5 and 2.0 and does two jobs. It finishes what 1.5 left open: a hub with real publications and community models, third-party plugins, the R and Julia packages’ second round, and the reviews by people that automated checks cannot replace. It builds 2.0’s riskiest designs early, as opt-in previews: the one space protocol, the migration tool as a dry run, and the checkpoint format v2. Users try them on real models a full release before 2.0 makes them the default. And it gives Studio the professional workbench it lacked. Nine epics, eight sprints, all on Windows, macOS and Linux (see Platforms). Backward compatible with 1.5: 1.6 adds and deprecates, it removes nothing. As the last 1.x minor, 1.6 becomes the long-term-support line for people who cannot move to 2.0 yet.

Epics#

I1 · Studio workbench#

Goal: Studio looks and works like the professional tools its users know (JupyterLab, VS Code, RStudio): the model’s views take the space, the controls are where the eye expects them.

Work items: the workbench layout (top run bar with the live step, activity bar opening the Parameters and Export panels, document tabs, timeline bar, status bar); a dark theme that follows the system setting; keyboard shortcuts (space to play or pause, the arrow keys to step and scrub, a list of them on ?); a side panel that can be resized; the space view drawn in the same style as the rest (frame, ticks, palette); tabs grouped when there are many (views, studies, tools, sharing); the open tab and panel remembered per browser.

Done when: axe-core finds no WCAG A or AA violation in the light and dark themes; the browser tests pass on Chromium, Firefox and WebKit; five people who have never used Studio open a model, change a parameter, scrub back and export a figure without help.

Progress (S1): the workbench layout (modelly/studio/shell.py, modelly/templates/studio.css), with the four translations, no WCAG A or AA violation, and the guide’s screenshots retaken by tools/studio/screenshots.py.

Size: M · Depends on: 1.5 G7, G8

I2 · The hub in practice#

Goal: the hub holds published, citable work, not only the zoo.

Work items: the first real Zenodo publication with a DOI, and Sigstore signing outside dry runs; install and verify checked on Windows and macOS as well as Linux; three community models reviewed and listed; a “publish your model” walkthrough timed from project to DOI.

Done when: at least one model has a real DOI and a verified signature; three community models are listed; publishing takes under ten minutes, timed.

Size: M · Depends on: 1.5 G1, G2

I3 · Plugins in the wild#

Goal: the plugin API v1 proven by plugins Modelly’s authors did not write.

Work items: three third-party plugins (a space, an executor, a Studio view) listed on the hub and tested against 1.6 on all three platforms; the plugin guide revised from their authors’ questions.

Size: S · Depends on: 1.5 G9

I4 · R and Julia II#

Work items: ggplot2 methods for the R package (carried over from 1.5 S4); the R package on r-universe, and a decision on CRAN; the Julia package in the General registry; the R and Julia tutorials run on all three operating systems in the release workflow.

Size: M · Depends on: 1.5 G6

I5 · Language-model agents: providers compared#

Work items: the evaluation harness run on three real providers and a local model, on the conversational market and one more model: agreement between providers, cost and latency per step, reported in the guide; recorded replies kept so the comparison replays offline.

Size: S · Depends on: 1.5 G5

I6 · Builder II#

Work items: the Studio builder with several agent classes, grids, networks and continuous space, and more behaviours; the code it writes passes modelly lint and runs unchanged.

Size: M · Depends on: 1.5 G7, G10

I7 · Accessibility and languages II#

Work items: the French, Spanish, Portuguese and Chinese translations reviewed by native speakers; keyboard-only and screen-reader passes by hand (NVDA on Windows, VoiceOver on macOS, Orca on Linux) of Studio and the docs, their findings fixed and the method written down.

Size: S · Depends on: 1.5 G8

I8 · 2.0 previews: space protocol, migration, formats#

Goal: 2.0’s three riskiest designs used on real models before they become the default.

Work items:

  • Space protocol (2.0 H2), provisional: the Space protocol (place, move, neighbors, within, positions) implemented by grids, networks, continuous and geographic space, opt in per model; today’s classes unchanged. A tutorial switches a model from grid to network to continuous space by changing one line.

  • Migration dry run (2.0 H1): modelly migrate --to 2.0 --dry-run prints the diff it would apply and a report of what needs a human, and writes nothing.

  • Checkpoint format v2 (2.0 H8), opt in: columns as Arrow, structure as JSON, only user objects pickled; 1.6 reads and writes it, so 2.0 checkpoints can come back to the long-term-support line.

Done when: every zoo model runs on the space protocol in the test suite with the same results; the dry run reports on every zoo and hub model; every zoo model’s checkpoint round trips through format v2 and resumes with the same results.

Size: L · Depends on: 1.5 G11; designs in 2.0.0 H1, H2, H8

I9 · Quality and platforms#

Work items: the release gate as for 1.5 (benchmark against the previous release, the notebooks, the three-OS matrix, the accessibility stage); the public names’ stability list (docs/api_stability.toml) kept in step with the previews, which enter as provisional; 1.6 announced as the long-term-support line.

Size: S (continuous)
