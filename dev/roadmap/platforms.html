Platforms: Windows, macOS and Linux#

Rule: a feature ships only when it works on Windows, macOS and Linux, with the same results for the same seed. A feature that cannot (for example, a SLURM executor, which needs a Linux cluster) must still be usable from all three: you submit from your Windows or macOS laptop, the cluster runs Linux.

Engineering rules that keep it true#

  1. CI tests on all three. The build workflow already runs the suite on Ubuntu, macOS and Windows; every new test runs there. The release workflow builds and import-tests wheels for each platform before anything is published.

  2. A local gate that runs everywhere. scripts/ci-local.sh is bash. 1.3.0 adds python -m modelly.dev gate, the same stages in Python, so contributors on Windows run the same gate without WSL or Git Bash.

  3. No Unix tools in library code. No calls to sh, taskset, curl or sed from modelly/. Scripts that users run (data downloads, benchmarks) are Python, not bash. modelly bench pins CPUs with psutil where the OS allows it (Linux, Windows) and says so where it does not (macOS).

  4. Paths and text. pathlib everywhere; every open() of a text file names encoding="utf-8" (Windows defaults to a legacy code page); manifests store paths relative and in POSIX form; hashes are taken over bytes, never over text with platform line endings. The ruff rule for unspecified encodings is turned on in 1.3.

  5. Files that are written while read. Checkpoints and result stores are written to a temporary file and moved into place with os.replace, which is atomic on all three and avoids Windows sharing violations.

  6. Native code for three compilers. Every C module builds with GCC, Clang and MSVC, at warning level -Wall / /W4, with no compiler extensions outside an #ifdef. Thread safety is checked with ThreadSanitizer on Linux and macOS and by the free-threaded test suite on all three.

  7. Optional dependencies must have wheels for all three. A library that needs a system install on one OS is not accepted as a dependency of a shipped feature.

  8. Determinism across platforms. The determinism suite (1.3) runs every example, compiled and pure, saved and loaded, on all three and compares the outputs byte for byte; floating-point outputs that legitimately differ (for example a GPU reduction) are listed with their tolerance.

  9. Docs for both shells. Where a command differs between bash and PowerShell, the docs show both.
