## DataCollector

`DataCollector` takes `add_table_row` from `modelly.data.tables` and the `get_*_dataframe` methods from `modelly.data.frames`; they are listed under `DataCollector`.

Modelly Data Collection Module.

DataCollector is meant to provide a simple, standard way to collect data generated by a Modelly model. It collects four types of data: model-level data, agent-level data, agent-type-level data, and tables.

A DataCollector is instantiated with three dictionaries of reporter names and associated variable names or functions for each, one for model-level data, one for agent-level data, and one for agent-type-level data; a fourth dictionary provides table names and columns. Variable names are converted into functions which retrieve attributes of that name.

When the collect() method is called, each model-level function is called, with the model as the argument, and the results associated with the relevant variable. Then the agent-level functions are called on each agent, and the agent-type-level functions are called on each agent of the specified type.

Additionally, other objects can write directly to tables by passing in an appropriate dictionary object for a table row.

**The DataCollector then stores the data it collects in dictionaries:**

- model_vars maps each reporter to a list of its values
- tables maps each table to a dictionary, with each column as a key with a list as its value.
- _agent_records maps each model step to the rows of each agent’s id and its values (an AgentRows sequence of tuples, stored by column).
- _agenttype_records maps each model step to a dictionary of agent types, each containing a list of each agent’s id and its values.

Finally, DataCollector can create a pandas DataFrame from each collection, and a pyarrow Table or a Parquet file (`to_arrow`, `to_parquet`).

#### `class DataCollector(model_reporters=None, agent_reporters=None, agenttype_reporters=None, tables=None)`

Class for collecting data generated by a Modelly model.

A DataCollector is instantiated with dictionaries of names of model-, agent-, and agent-type-level variables to collect, associated with attribute names or functions which actually collect them. When the collect(…) method is called, it collects these attributes and executes these functions one by one and stores the results.

Instantiate a DataCollector with lists of model, agent, and agent-type reporters.

Both model_reporters, agent_reporters, and agenttype_reporters accept a dictionary mapping a variable name to either an attribute name, a function, a method of a class/instance, a partial function, or a function with parameters placed in a list.

Model reporters can take five types of arguments:

```default
{"agent_count": lambda m: len(m.agents)}                  # lambda
{"agent_count": self.get_agent_count}                     # bound method
{"agent_count": Model.get_agent_count}                    # method of a class
{"model_attribute": "model_attribute"}                    # attribute name
{"agent_count": functools.partial(count_agents, multiplier=2)}
{"Model_Function": [function, [param_1, param_2]]}        # function + params
```

Agent reporters can similarly take:

```default
{"energy": "energy"}                                      # attribute name
{"energy": lambda a: a.energy}                            # lambda
{"agent_action": self.do_action}                          # bound method
{"agent_action": Agent.do_action}                         # method of a class
{"energy": functools.partial(get_energy, scale=2)}
{"Agent_Function": [function, [param_1, param_2]]}        # function + params
```

Agenttype reporters take a dictionary mapping agent types to dictionaries of reporter names and attributes/funcs/methods, similar to agent_reporters:

```default
{Wolf: {"energy": lambda a: a.energy}}
```

The tables arg accepts a dictionary mapping names of tables to lists of columns. For example, if we want to allow agents to write their age when they are destroyed (to keep track of lifespans), it might look like:

```default
{"Lifespan": ["unique_id", "age"]}
```

**Parameters:**

- **model_reporters** – Dictionary of reporter names and attributes/funcs/methods.
- **agent_reporters** – Dictionary of reporter names and attributes/funcs/methods.
- **agenttype_reporters** – Dictionary of agent types to dictionaries of reporter names and attributes/funcs/methods.
- **tables** – Dictionary of table names to lists of column names.

Notes

- If you want to pickle your model you must not use lambda functions.
- If your model includes a large number of agents, it is recommended to use attribute names for the agent reporter, as it will be faster.
- agenttype_reporters collect only agents of exactly the given type. Subclasses are not included, so a reporter keyed on a superclass does not pick up its subclasses. Add a separate reporter per concrete type if you need subclass data.

## Arrow, Parquet and DuckDB

`DataCollector.to_arrow` and `DataCollector.to_parquet` call these functions; `query` runs SQL over Arrow tables, DataFrames and Parquet files. They need `pip install "modelly-abm[experiments]"`.

Arrow and Parquet export of a DataCollector, and SQL over the results with DuckDB.

pyarrow and duckdb are optional: `pip install "modelly-abm[experiments]"`. Parquet files are written atomically (a temporary file in the same folder, then `os.replace`), so a reader never sees half a file, on any platform.

Example

```default
>>> collector.to_parquet("runs/model.parquet")
>>> query("SELECT avg(Gini) FROM model", model=collector.to_arrow())
```

#### `to_arrow(collector: Any, kind: str = 'model', name: Any = None) → Any`

One collection of `collector` as a `pyarrow.Table`.

**Parameters:**

- **collector** – a DataCollector.
- **kind** – `"model"`, `"agent"` (with `Step` and `AgentID` columns), `"agenttype"` or `"table"`.
- **name** – the agent class for `"agenttype"`, the table name for `"table"`.

Example

```default
>>> table = to_arrow(model.datacollector, "agent")
```

#### `write_parquet_atomic(table: Any, path: str | Path) → Path`

Write a `pyarrow.Table` to `path` atomically; return the path.

The table goes to a temporary file next to `path` first, then `os.replace` moves it into place, so a crash leaves no partial file.

#### `to_parquet(collector: Any, path: str | Path, kind: str = 'model', name: Any = None) → Path`

Write one collection of `collector` to a Parquet file, atomically.

Arguments are those of [`to_arrow()`](https://remipelloux.github.io/Modelly/apis/data.html#modelly.data.io.to_arrow); returns the path written.

Example

```default
>>> to_parquet(model.datacollector, "out/agents.parquet", "agent")
```

#### `query(sql: str, connection: Any = None, **tables: Any) → Any`

Run `sql` with DuckDB over named tables; return a DuckDB relation.

Each keyword names a table in the query: a `pyarrow.Table`, a pandas DataFrame, or a path (or glob) of Parquet files.

Example

```default
>>> query("SELECT count(*) FROM runs", runs="out/*.parquet").fetchone()
```

#### `tables_of(collector: Any) → Mapping[str, Any]`

Every non-empty collection of `collector` by name: `model`, `agent` and its tables.

## Reporters

The functions behind the collector: reporter normalisation and the fast row-collection paths.

Reporter plumbing for [`modelly.data.collector.DataCollector`](https://remipelloux.github.io/Modelly/apis/data.html#modelly.data.collector.DataCollector).

A reporter is what the user hands the collector: an attribute name, a callable, a bound method, a `functools.partial` or a `[function, [params]]` list. The functions here normalise them once at registration and then gather values as cheaply as possible on every `collect`:

- attribute reporters are gathered with a single `operator.attrgetter` per agent, so the per-agent work happens in C;
- a value is copied only when it is mutable, so the common scalar case costs a set lookup instead of a `deepcopy` call.

#### `snapshot(value: Any) → Any`

Return `value` itself when immutable, otherwise a deep copy.

Stored values must not change when the model mutates them on a later step.

#### `check_list_reporter(name: str, reporter: list) → None`

Validate that a list-style reporter has the form [callable, [params]].

#### `validate_model_reporter(name: str, reporter: Any, model: Any) → None`

Run a model reporter once so a broken definition fails loudly on first collect.

**Raises:**

- [**ValueError**](https://docs.python.org/3/builtins/exceptions.html#ValueError) – If reporter has an invalid list format
- [**AttributeError**](https://docs.python.org/3/builtins/exceptions.html#AttributeError) – If model attribute doesn’t exist
- [**RuntimeError**](https://docs.python.org/3/builtins/exceptions.html#RuntimeError) – If reporter execution fails

#### `compile_model_reporter(name: str, reporter: Any) → Callable[[Any], Any]`

Turn a model reporter definition into a plain `callable(model)`.

The type dispatch happens here, once, instead of on every `collect`. List reporters are re-checked on every call: the list is user-owned and may have been edited after validation.

#### `getattr_or_none(model: Any, name: str) → Any`

`getattr` with a `None` default, as model attribute reporters have always behaved.

#### `collect_model_value(name: str, reporter: Any, model: Any) → Any`

Evaluate one model reporter against `model` and return a stored-safe value.

List reporters are re-checked on every call: the list is user-owned and may have been edited after validation.

#### `make_agent_reporter(name: str, reporter: Any) → Callable[[Any], Any]`

Normalise an agent reporter definition into a one-argument callable.

Attribute names become a getter that raises a descriptive AttributeError and carries the attribute in `_modelly_attribute` so collection can use the C fast path. `[function, [params]]` lists are bound. Anything else is already a suitable callable and is returned as is.

#### `collect_agent_rows(agents: Iterable[Any], reporters: dict[str, Callable], time: float, one_type: bool = False) → AgentRows`

Return the `(time, unique_id, *values)` rows of every agent, stored by column.

Values are gathered one reporter at a time over all agents (a C-level `map` per column), so the per-agent Python work is close to zero. A column is copied only if it holds a mutable value. Attribute reporters use one `attrgetter`; a missing attribute re-runs the reporter’s own getter to produce the descriptive error.

When every reporter is a `Column` of the agents’ single class and `agents` is that class’s whole population, the rows are sliced straight out of the column table in table order, with no per-agent work at all. `one_type` says the caller knows every agent has the same class.

## Recorders

Collection schedule for one dataset: interval, time window and sliding window.

#### `class DatasetConfig(interval: int | float = 1, start_time: int | float = 0, end_time: int | float | None = None, window_size: int | None = None, enabled: bool = True, _next_collection: int | float = 0, _last_collection: int | float = -1)`

**Variables:**

- **_next_collection** ([*int*](https://docs.python.org/3/builtins/functions.html#int)* | *[*float*](https://docs.python.org/3/builtins/functions.html#float)) – Next scheduled collection time (internal)

Examples

# Collect every step from 0 to infinity DatasetConfig(interval=1, start_time=0)

# Collect every 5 steps from 100 to 500 DatasetConfig(interval=5, start_time=100, end_time=500)

# Collect every step, keep only last 1000 snapshots DatasetConfig(interval=1, start_time=0, window_size=1000)

# Warmup phase: skip first 100 steps, collect 100-200 DatasetConfig(interval=1, start_time=100, end_time=200)

#### `class NumpyJSONEncoder(*, skipkeys=False, ensure_ascii=True, check_circular=True, allow_nan=True, sort_keys=False, indent=None, separators=None, default=None)`

Bases: [`JSONEncoder`](https://docs.python.org/3/library/json.html#json.JSONEncoder)

JSON Encoder that handles Numpy types.

Constructor for JSONEncoder, with sensible defaults.

If skipkeys is false, then it is a TypeError to attempt encoding of keys that are not str, int, float, bool or None. If skipkeys is True, such items are simply skipped.

If ensure_ascii is true, the output is guaranteed to be str objects with all incoming non-ASCII characters escaped. If ensure_ascii is false, the output can contain non-ASCII characters.

If check_circular is true, then lists, dicts, and custom encoded objects will be checked for circular references during encoding to prevent an infinite recursion (which would cause an RecursionError). Otherwise, no such check takes place.

If allow_nan is true, then NaN, Infinity, and -Infinity will be encoded as such. This behavior is not JSON specification compliant, but is consistent with most JavaScript based encoders and decoders. Otherwise, it will be a ValueError to encode such floats.

If sort_keys is true, then the output of dictionaries will be sorted by key; this is useful for regression tests to ensure that JSON serializations can be compared on a day-to-day basis.

If indent is a non-negative integer, then JSON array elements and object members will be pretty-printed with that indent level. An indent level of 0 will only insert newlines. None is the most compact representation.

If specified, separators should be an (item_separator, key_separator) tuple. The default is (’, ‘, ‘: ‘) if *indent* is `None` and (‘,’, ‘: ‘) otherwise. To get the most compact JSON representation, you should specify (‘,’, ‘:’) to eliminate whitespace.

If specified, default is a function that gets called for objects that can’t otherwise be serialized. It should return a JSON encodable version of the object or raise a `TypeError`.

ParquetDataRecorder: snapshots buffered and written to .parquet files.

#### `class ParquetDataRecorder(model, config: dict[str, DatasetConfig | dict[str, Any]] | None = None, output_dir: str = '.')`

Bases: [`BaseDataRecorder`](https://remipelloux.github.io/Modelly/apis/data.html#modelly.data.recorders.base.BaseDataRecorder)

Store collected data in Parquet files, one per dataset.

Snapshots are buffered as DataFrames and written when the buffer holds `buffer_size` rows or as many rows as the file already has, whichever is more. A Parquet file cannot be appended to, so every write rewrites it; letting the buffer grow with the file keeps the total work linear in the rows recorded, where a fixed buffer made it quadratic. The buffer then holds at most as many rows as the file, which a write reads into memory anyway.

Initialize Parquet storage backend.
