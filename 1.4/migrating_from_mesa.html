Migrating from Mesa#

Modelly’s authoring model will feel familiar if you have written a Mesa model: a Model subclass owns the world, Agent subclasses hold behaviour, a DataCollector records. The differences are where Mesa accumulated several generations of API (schedulers, two grid systems, batch_run) and Modelly keeps one. This page maps every Mesa construct to its Modelly equivalent, for Mesa 2.x and Mesa 3.x code alike.

Start with the codemod. It rewrites the mechanical parts (imports, agent constructors, a few model attributes) and prints a report of every line that needs a decision, each pointing to a section below:

python -m modelly.migrate path/to/your/model/          # dry run: shows the diff and the report
python -m modelly.migrate path/to/your/model/ --write  # applies the rewrites

Then work through the report top to bottom. A typical Mesa 3 model is done after the imports; a Mesa 2 model needs the scheduler and grid sections.

The codemod does all of these, for import statements and for dotted names in code (mesa.discrete_space.CellAgent becomes modelly.space.CellAgent). A Mesa module with no Modelly equivalent is reported, not silently rewritten: the property-layer modules (mesa.space.property_layer, mesa.discrete_space.property_layer; use grid.create_property_layer, see Grids) and every other mesa.experimental.* module, such as mesa.experimental.devs (see Events).

Agents#

Constructor. Mesa 2 agents took an id; Modelly assigns unique_id itself, starting at 1:

# Mesa 2
class Sheep(mesa.Agent):
    def __init__(self, unique_id, model, energy):
        super().__init__(unique_id, model)


# Modelly (and Mesa 3)
class Sheep(Agent):
    def __init__(self, model, energy):
        super().__init__(model)

model.next_id() no longer exists; delete those calls. The codemod rewrites the super() call and flags the constructor signature so you remove the parameter from the callers too.

Random numbers. self.random and self.model.random work as in Mesa, and self.rng is a seeded numpy Generator. Never use the random module or np.random directly.

Creating many agents. Sheep.create_agents(model, n, energy=energies) creates n agents in one call; a sequence of length n gives one value per agent, anything else is broadcast.

Data collection#

DataCollector keeps Mesa’s API: model_reporters, agent_reporters, agenttype_reporters, tables, collect(model), get_model_vars_dataframe(), get_agent_vars_dataframe(), get_agenttype_vars_dataframe(type), get_table_dataframe(name). Attribute-name reporters ({"energy": "energy"}) are the fast path. Declaring an attribute as a Column makes model.columns[Sheep].energy a numpy view, which is the Modelly way to write a vectorised model reporter.

Batch runs#

Mesa’s batch_run(Model, parameters, iterations, max_steps, ...) becomes scenarios and a runner:

from concurrent.futures import ProcessPoolExecutor

from modelly.scenarios import RunConfiguration, run_scenarios

scenarios = [
    s
    for density in (0.6, 0.7, 0.8)
    for s in MyScenario(density=density, rng=1).spawn_replications(10)
]
config = RunConfiguration(MyModel, until=100)

with ProcessPoolExecutor() as pool:
    store = run_scenarios(scenarios, config, executor=pool)

Each replication has its own seed derived from the base scenario, so the sweep is reproducible. For a quick loop, for scenario in base.spawn_replications(n): model = MyModel(scenario). For a plain list of runs or a factorial grid with one seed per run, modelly.run_batch and modelly.run_grid (in modelly.batch) run them over processes; see Batch.

Events and simulators#

ABMSimulator, DEVSimulator and mesa.experimental.devs do not exist. The model schedules directly: self.schedule_event(fn, at=t) or after=dt, self.schedule_recurring(fn, Schedule(interval=2.0)), and run_for / run_until advance time through the same event list that drives step.

Visualization#

SolaraViz, SpaceRenderer, make_space_component, make_plot_component, Slider and the portrayal style classes keep their Mesa 3 names and signatures under modelly.viz. Mesa 2’s ModularServer and the JavaScript modules have no equivalent; rewrite those visualisations with SolaraViz (tutorial 6).

Checklist#

  1. Run the codemod, read the report.

  2. Replace schedulers with AgentSet calls; delete schedule.add.

  3. Move grid code to cells: agent.cell, cell.neighborhood, grid.select_random_empty_cell().

  4. Move parameters into a Scenario; pass rng instead of seed.

  5. Run your tests with -W error; Modelly raises instead of warning for removed APIs.
